# 数据来源登记表

> 本文件是 `data/` 下所有数据表的**唯一出处**。每条数据行带 `source_id` 与 `credibility`。
> **抓取日期：2026-10-03**

## 可信等级

| 等级 | 含义 | 在评估中的作用 |
|---|---|---|
| `official` | 厂商官方 API 文档 / 定价页 | 可直接作为测算依据 |
| `secondary` | 媒体、聚合站、技术博客 | 可作为依据，结论中必须显示来源 |
| `unverified` | 孤证或与官方口径矛盾 | **不参与测算**，仅列待核实项 |

> 与本项目其他部分一致的口径纪律：**查不到就写「未查到」，不用看起来合理的数字替代。**
> 这一点在 `evaluator.py` 中由测试强制：`test_no_fabricated_metrics` 会检查不存在编造的指标值。

## 峰谷分时口径（易错点，单独说明）

DeepSeek 自 2026-08-16 起实行**峰谷分时计费**：

| 时段（UTC） | 时段性质 | 单价 |
|---|---|---|
| 01:00–04:00、06:00–10:00 | 峰时 | 基准价 × 2 |
| 其余时段 | 谷时 | 基准价 × 1（表中所列即为谷时价） |

- 峰时按**自然小时**判定，跨零点不合并。
- 本项目按「峰时占比」参数折算混合单价，取值登记在 `data/assumptions.md` A-05。
- 缓存命中价仅在供应商公布时才有；未公布的模型按**全价**计入混合成本（本项目两个模型均已公布）。

## 与既有作品集的边界

本项目**不做算力采购测算**（卡数 / TCO / BOM），那是 `ai-compute-presales-workbench` 的范围。
本项目只回答「**该用哪条技术路线、效果够不够、每月花多少**」——
`sizing.py` 算的是向量库规模、上下文预算与 Token 消耗，不是服务器采购。
